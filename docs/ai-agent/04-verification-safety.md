# 04. 검증과 안전 — AI가 했다고 믿지 말고 확인하기

## 최소 점검 루프
1. **범위 확인:** 현재 경로(`pwd` 또는 `Get-Location`)와 프로젝트 위치
2. **무엇을 바꿨는가:** `git status --short` → `git diff --stat` → `git diff`
3. **새 파일도 확인:** `git diff`에 표시되지 않는 미추적 파일은 편집기로 열어 검사
4. **실제로 실행했는가:** 명령, 종료 코드, 출력, 테스트 개수를 기록
5. **정답 검증:** 소계 6,000원 및 완성 총액 10,500원을 손으로 재계산
6. **자료 품질:** 빈 값, 누락 가격, 음수 수량, 잘못된 CSV 행 등 반례 추가

## 명령 (모든 OS 공통)
~~~bash
git status --short
git diff --check
git diff -- agent_lab
python3 -m unittest discover -s agent_lab -p 'test_*.py'
~~~
Windows에서는 마지막 명령을 `py -m unittest discover -s agent_lab -p "test_*.py"`로 실행할 수 있다.

## 금지/승인 경계
| 작업 | 원칙 | 이유 |
|---|---|---|
| 설명 및 읽기 | 허용 범위에서 진행 | 데이터 이해 |
| 코드/테스트 작성 | **실습 폴더만** | 다른 과제 보호 |
| 패키지 설치 | 명령을 보여 주고 승인 | 공급망·환경 변경 |
| `rm -rf`, `del`, 강제 초기화 | 강사 확인 전 실행 금지 | 복구 어려움 |
| 외부 업로드·메일·API 통신 | 별도 동의 전 금지 | 개인정보·정보 유출 |
| `git push`, 자동 배포 | 승인 전 금지 | 외부 변경 |
| 무제한 실행 승인 / 샌드박스 해제 | 사용하지 않음 | 의도하지 않은 실행 |

## 비밀정보와 인용
API Key, 계정 정보, 토큰, 개인 연락처가 들어간 파일을 에이전트의 작업 범위에 두지 않는다. 환경 변수나 `.env`는 Git에 올리지 않는다. AI가 만든 보고서의 사실·수치·출처는 원본과 대조한다.

## 일부러 실패시키기
쇼핑 목록에 `["라면", -2]` 또는 `["없는품목", 3]`을 추가한다. 에이전트가 결과를 조용히 확정하거나 임의 가격으로 채웠다면 **실패**다. 음수는 입력 오류로 알려야 하고, 미등록 품목은 총액을 미확정으로 처리해야 한다.

## 복구
변경 전후 `git diff`를 보관한다. 되돌리려는 파일을 정확히 확인한 다음 해당 파일만 복구한다. `git reset --hard` 등 광범위한 강제 복구 명령은 교육 초반에 사용하지 않는다.
