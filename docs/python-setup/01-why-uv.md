# 왜 uv를 사용하는가?

**uv**는 Python 버전·가상환경·패키지를 명령어(CLI)로 관리하는 빠른 도구다.

| 왜 uv인가? | 핵심 |
|---|---|
| **CLI 중심** | 설치 과정을 명령어로 기록·반복할 수 있어 AI와 협업하기 쉽다. |
| **Python 자동 설치** | 필요한 버전이 없으면 내려받아 가상환경을 만든다. |
| **버전별 환경** | 프로젝트마다 다른 Python과 패키지를 사용할 수 있다. |
| **빠른 설치** | 패키지 다운로드·의존성 처리와 캐시 재사용이 빠르다. |
| **공간 효율** | 공유 캐시와 파일 링크로 중복 다운로드·저장을 줄일 수 있다. |

## 질문으로 이해하기

**Q. python.org에서 Python을 먼저 설치해야 하나?**  
A. 아니다. uv를 설치한 뒤 다음 명령만 실행하면 된다.

```bash
uv venv
```

사용 가능한 Python이 있으면 재사용하고, 없으면 기본 설정에서 자동 다운로드한다. 현재 폴더에 `.venv`를 만든다. 특정 버전이 필요할 때만 `uv venv --python 3.14`처럼 지정한다.

**Q. Python 버전이 여러 개 필요할까?**  
A. 보통은 하나면 충분하다. 다만 기존 프로젝트나 GPU 라이브러리의 호환성 때문에 버전별 환경이 필요할 수 있다.

**Q. uv를 쓰면 디스크 공간을 거의 사용하지 않나?**  
A. 그렇지는 않다. 캐시와 `.venv`는 공간을 사용한다. 다만 같은 패키지를 재사용해 불필요한 중복을 줄인다.

**Q. uv를 설치하면 Git도 설치되나?**  
A. 아니다. Git은 코드 변경 이력을 관리하는 별도 도구다.

> **핵심:** Python을 설치하는 것보다 **필요한 실행환경을 만들고, 확인하고, 다시 만드는 것**에 집중한다.
